General Translation is the default machine translation provider for `inlang machine translate`. Without a provider setting or a bring-your-own key, the command uses the General Translation key from `GT_API_KEY` (or `.env` / `.env.local` next to `project.inlang`). In an interactive terminal without a key, it asks which translation provider the project should use. General Translation (recommended) signs in, in the browser or, where none can be shown or with `--no-browser`, with a code; lets you choose one of your General Translation projects or create one; and saves a development key to `.env.local` and the project ID to `gt.config.json`, so teammates use the same project. Community translation service uses the free community service, as before, and saves that choice to `.env.local`, so later runs don't ask again. Other links to the setup for another provider and saves nothing. In CI and other non-interactive runs without a key, it keeps using the free community service, as before, and prints how to set up General Translation. A project that chose General Translation, with a project ID in `gt.config.json` or `GT_PROJECT_ID`, or with `INLANG_MACHINE_TRANSLATE_PROVIDER=gt`, fails instead and explains how to get a key, so a missing CI secret never sends its text to another service. On a machine signed in to General Translation, as with the `gt` CLI, such a run saves a development key instead, without asking; without a project ID, it creates a project only for an account that has none.

Bring-your-own keys keep working and still take precedence when set. `INLANG_MACHINE_TRANSLATE_PROVIDER=gt` selects General Translation explicitly. General Translation authentication, billing and service failures never fall back to another provider. `INLANG_MACHINE_TRANSLATE_PROVIDER=demosjarco` still selects the community service. Each run that uses it now names it in one line instead of a three-line warning.

A run with nothing to translate no longer needs a provider.

Unreadable or invalid `gt.config.json` fails instead of being treated as an unconfigured project. Equivalent project paths, including `--project .` from inside the inlang project, find the same adjacent GT configuration and credentials.
